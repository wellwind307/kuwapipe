## 轮次 1：排查第三方 IP 许可风险

- **背景**：工程已上板跑通，进入提交准备。需要确认"提交包里能不能包含收集来的 IP"，尤其
  是摄像头采集模块。模型从 `ready_to_test/base.hwh` 反查实际例化的 IP（VLNV），逐个读版权头。
- **提示词**（原文粘贴）：
  ```
  【待填：当时的提问原文，例如"帮我把工程里所有用到的第三方 IP 列出来，逐个看许可"】
  ```
- **模型回答要点**：
  ```
  正点原子 cmos_capture_data.v 头部为 "All rights reserved / 盗版必究"，属专有代码，
  随开发板附赠仅供购买者学习使用，放进参赛包属再分发、超出默示许可范围。
  Digilent rgb2dvi/axi_dynclk 为 MIT/BSD-3；Xilinx PYNQ base overlay 为 BSD-3；均需保留声明。
  Kuwahara 是 1976 公开文献，无专利无版权。
  ```
- **是否采纳**：**采纳**。结论与后续处理全部依此展开。
- **自我纠错**：初版把"整个工程里满屏的 AMD 版权头"误当成风险，经核对是 Vivado 生成的 RTL
  头（许可范围内），随后修正为"保留头、声明即可"，而不是删掉。
- **产出**：`IP审查报告_kuwahara_btn.md`、`THIRD_PARTY_NOTICES.md`、`third_party/` 许可全文。

## 轮次 2：决定自研替换、而非上网找现成 IP

- **背景**：确认正点原子采集 IP 无开源许可后，面临两条路：① 上网找一个开源 OV5640 采集 IP
  替换；② 自研重写并做等价性验证。
- **提示词**（原文粘贴）：
  ```
  【待填：例如"采集 IP 有版权问题，能不能直接找开源的替代？还是自己写？"】
  ```
- **模型回答要点**：
  ```
  建议自研 + 逐拍等价性验证，理由：开源的 OV5640 DVP 采集 IP 接口语义（字节序、消隐期行为、
  复位语义）与本 BD 的 vid_io 接口未必一致，替换后仍需重新验证；且"能出图"不等于等价，
  下游时序敏感时必须给出可量化的等价判据。自研只需覆盖 DVP 同步 + RGB565→RGB888 + 上电稳定计数。
  ```
- **是否采纳**：**采纳**。
- **自我纠错**：模型最初倾向于"直接复用现成 IP 更快"，团队评估后坚持等价性可证明性优先，
  模型据此调整为自研 + 协同仿真方案。
- **产出**：`base.srcs/sources_1/new/ov5640_capture.v`、`ip_repo_local/ov5640_capture/`。

## 轮次 3：设计逐拍等价性仿真（不是"看图"）

- **背景**：自研采集模块写好，需要一个可信的 PASS 判据来证明与原 IP 等价。
- **提示词**（原文粘贴）：
  ```
  【待填：例如"怎么证明我重写的采集模块和原来那个完全等价？"】
  ```
- **模型回答要点**：
  ```
  写一个 TB 并排例化"原 IP（仅仿真参考）"与"自研模块"，喂同一组 cam_pclk/vsync/href/data，
  逐拍用 !== 比较全部输出（含 X 检测）；复位瞬态用 cmp_hold 屏蔽；激励覆盖复位释放、多帧连续、
  消隐随机抖动、运行中复位后再对齐；PASS 写成"0 失配 且 比较拍数 > 阈值"。
  ```
- **是否采纳**：**采纳**。
- **自我纠错**：初版只比数据总线，模型提醒会漏掉 `ce/vsync/href` 的错拍，改为比全部输出。
- **产出**：`vs_sim/tb_ov5640_capture.v`、`vs_sim/prepare_capture_ref.py`（现场转 UTF-8 + 补
  timescale，参考副本不进提交包）。

## 轮次 4：仿真抓出真实差异（消隐期保持 vs 清零）

- **背景**：等价性仿真第一次跑出失配。
- **提示词**（原文粘贴）：
  ```
  【待填：例如"仿真 mismatch 不是 0，帮我定位是哪一拍、什么信号差"】
  ```
- **模型回答要点**：
  ```
  差异在消隐期：原 IP 在消隐期保持最后一个像素（data hold），自研初版清零。属于行为语义
  差异，不是时序错拍；把自研版改为消隐期保持即可对齐。
  ```
- **是否采纳**：**采纳**，改为一致行为后重跑 PASS。
- **自我纠错**：模型初判"可能是复位时序问题"，团队按逐拍差分定位到消隐期数据保持差异后，
  模型修正结论并给出修改点。
- **产出**：`ov5640_capture.v` 修正 + `sim/ov5640_equiv_sim.log`（91,063 拍 / 0 失配 / PASS）。

## 轮次 5：Vivado 集成三个坑（打包、IP 仓库路径、端口名）

- **背景**：把自研模块接进 BD 替换原单元时连续报错。
- **提示词**（原文粘贴）：
  ```
  【待填：例如"用 module_ref 接进去报 clock pins not connected，怎么处理？"】
  ```
- **模型回答要点**：
  ```
  ① module_ref 的输出不被 BD 当作时钟源，必须 ipx::package_project 打包成 IP；
  ② set_property ip_repo_paths 是覆盖不是追加，会丢掉 Digilent 仓库，要用追加；
  ③ 端口名撞已有接口定义（cmos_frame_*）会凭空推断出多余接口，改名为 vid_*。
  ```
- **是否采纳**：**采纳**，三个坑全部按此解决。
- **自我纠错**：模型一度建议"手动 create_bd_pin 两头连"，实测报 "sink already connected"，
  改为 `connect_bd_net` 跨层次直连（BD 自动生成边界引脚）。
- **产出**：`package_capture_ip.tcl`、`modify_capture.tcl`；沉淀为技能 `skill/README.md` S2。

  ```
  【待填：例如"提交包要剔除哪些目录、许可声明和承诺书怎么写才不算虚假陈述"】
  ```
- **模型回答要点**：
  ```
  剔除 base.runs/base.cache/base.hw/.Xil/vs_sim/work/*.log/*.jou 等纯构建产物；ipshared 不能
  一刀切删（含 AMD/Digilent/PYNQ 生成源码），只删正点原子 ipshared/949d/；承诺书如实勾选
  "使用第三方 IP"并附清单，切忌写"全部原创"；保留开发时间线证据。
  ```
- **是否采纳**：**采纳**。
- **自我纠错**：模型初稿建议"删掉整个 ipshared/ 保持干净"，团队指出会导致工程无法再综合，
