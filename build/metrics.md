# 指标汇总表

> 填表规则：每一项都要写清「实测 / 仿真 / 设计值」，并注明测试条件与出处文件。
> **功能一致性的证据必须来自仿真**；板上只证明「功能正常、帧率达标、处理确实生效」。

## 1. 测试条件

| 项 | 值 |
|---|---|
| 板卡 / 器件 | `xc7z020clg400-2`（正点原子领航者 ATK-DF7010/7020P，PYNQ-Z2 兼容） |
| PYNQ 镜像 | 厂商镜像 `Release 2025_08_27`（含 `pynq.lib.ov5640`，官方镜像没有） |
| 工具版本 | Vivado 2025.2 |
| 输入 | OV5640，RGB565，800x480（HTS=1800，VTS=1000） |
| 显示 | HDMI 640x480（DVI 只支持固定模式，右侧裁 20%） |
| 采集场景 | 静止场景 |
| 测量脚本 | `board/measure.py` |

## 2. 功能正确性（仿真证据，非板上）

| 指标 | 数值 | 出处 |
|---|---|---|
| 全尺寸密集流逐位一致 | **384000 / 384000 像素，mismatch 0** | `sim/logs/kw_sim_full800x480.log` |
| 与 golden 的差异（内部像素） | **0 LSB（300516 / 300516 像素逐一相同）** | `sim/verify_kuwahara.py`（2026-11-04 复跑 PASS） |
| 边界差异来源 | RTL 补零 vs golden replicate，仅最外 3 行/列（3157 像素，1.03%） | `sim/verify_kuwahara.py` |
| 采集 IP 等价性 | 与原厂实现 **91063 拍 0 失配** | `sim/logs/ov5640_equiv_sim.log` |
| 模式切换自校验 | 输出 13292 拍 0 失配（输入 13296，切换瞬态丢 4 拍） | `sim/logs/mode_switch_sim.log` |

> **为什么不做「板上 vs golden 逐像素比对」**：Kuwahara 的象限选择是 `argmin(方差)` 的**离散判决**，
> 输入几 LSB 的噪声就可能翻转象限，输出随之差出几十；加上两次抓帧本就是不同帧、自动曝光会微动。
> 因此该比对天然不收敛，不能作为判据。板上只做功能演示与性能测量。

## 3. 板上性能（实测）

| 指标 | 数值 | 类型 | 方法 |
|---|---|---|---|
| 输出帧率 | **40.05 fps**（10 s，401 帧全不重复） | 实测 | `measure.py fps --seconds 10` |
| 帧率上限来源 | OV5640 时序：HTS=1800、VTS=1000，`PCLK ≈ 40.05×1800×1000 ≈ 72.1 MHz` | 反推 | 由实测 fps 与寄存器常量反算 |
| 相邻帧噪声地板 | mean **15.8~21.9** / max 174~232 / 差异像素 **~99%** | 实测 | `measure.py noise`；判定为 **50 Hz 工频 + AE 呼吸**，非传感器噪声 |
| 处理 vs 直通差异 | mean **5.97**（单次） | 实测 | `measure.py compare` 首行（证明切换生效） |

> 40.05 fps 是**读帧计数**得到的结果（按不重复帧去重），不等于用仪器测的 HDMI 刷新率；
> 「每个指标重复 3 次取中位数」尚未做（见第 7 节）。

## 4. 吞吐与延迟（设计值）

| 指标 | 数值 | 说明 |
|---|---|---|
| 处理吞吐（峰值） | 1 pixel/clk @ 100 MHz = **100 Mpixel/s** | 约为有效输入需求 15.38 Mpixel/s 的 6.5 倍 |
| 单帧处理占用 | 483x808 = 390,264 clk ≈ **3.90 ms** | 含扩展网格 flush |
| 占帧周期比例 | **15.6%**（3.90 ms / 24.97 ms @40.05 fps） | 余量充足 |
| 帧内延迟 | 3×808+3+5 = **2432 拍 ≈ 24.32 µs** @100 MHz | 不含中值、DDR 与显示等待 |
